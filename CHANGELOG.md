## [0.1.0] - 2026-10-07
### Added
- the project notes (English summary of everything known about the file formats and parameters) and the project notes (translated) are part of the public documentation.
- Spanish and Italian catalogs (`translations/es.json`, `it.json`); the decoding status in brackets ([likely], [hypothesis]) is translated; the e-mail address in the About dialog opens the mail program.
- Speed: opening a file of the same type and model updates the existing table in place instead of rebuilding about 1000 widgets (6-9 s -> 0.4-2 s); `tools/run_checks.py` runs single test blocks (`--only`) and prints the time per block; every profile (type, model) keeps its built table, so switching between SCENE/ALL and between the models only updates values (about 2 s instead of 8); the full test run dropped from 17 to under 7 minutes.
- Logo (`assets/sonyconfigeditor.png`) in the About dialog (transparent margin cropped, scales with the display scaling) and in the README; bundled by `build_exe.bat` / `build_app.sh`.
- **Menu bar** instead of the toolbar buttons (own scalable, dark bar; File: New, Open, Save, Save As, Import, Exit; Edit: Undo, Redo, Find; View: Language; Help: About) with the usual shortcuts (Ctrl+N/O/S/Shift+S/I/Z/Y/F/Q, F1). About dialog with copyright (pseudonym "Lukas Himmelswanderer"), unofficial/no-warranty disclaimer towards Sony and the licence text; `LICENSE` (MIT).
- **Language switch at run time** (View > Language): all texts are translatable (English source texts in the code are the keys, catalogs in `translations/<code>.json`, `translate_db` for the notes/labels/dropdowns of the databases, `_label_words` for generated format labels); German is a catalog (`de.json`), English is the default and source language. Buttons and dropdowns take the width of the longest translation. `tools/i18n_keys.py` lists the keys and missing translations.
- **Settings file** (language, last folder) in the user's config directory (Windows `%APPDATA%`, macOS `Library/Application Support`, Linux `$XDG_CONFIG_HOME`; portable: `settings.json` next to the program). Size-limited, type-checked, no network paths, atomic write.
- **Hardened file loading**: limits for file size (64 KB), lines, ID format (5 digits), duplicate IDs, value length/fields, control characters, model and name; hostile files are rejected with a message (tests 44).
- `build_app.sh` (PyInstaller for Linux/macOS, untested), requirements in the header of `SonyConfigEditor.py`; tests record every message box instead of showing it.
- Step fields (User Matrix, Skin Detail) put as many cells in a line as fit into the window and wrap only when it is narrow (reflow while resizing).
- The start window is wider (1150 instead of 900 logical pixels, limited to 90 % of the screen) so that the Multi Matrix row (axis, hue, saturation) is no longer cut off at the edge.
- Fix: after a lock was released (e.g. White Clip Off -> On, Cine EI -> Custom) the number fields of that row stayed uneditable: the inner entry of a field was disabled a second time and kept the disabled state. Typing and the display of values work again; the checks now look at the inner entry.
- Format list: 39 formats of the manuals (NTSC and PAL, all codecs) added as marked assumptions ("– Annahme"); the codec dropdown shows its raw value; IDs and raw values appear in grey brackets behind the decoded text (rows and dropdowns).
- Multi Matrix: the axis dropdown has a label above it and sits on the same level as the hue and saturation fields.
- White Clip Setting is locked (greyed out) with Gamma Category S-Log2/S-Log3, as the manual says; S&Q Motion On/Off now comes before the S&Q frame rate. the project notes lists all menu dependencies found in the manuals (done / open).
- The yellow "changed" border of step fields and multi-choice dropdowns now sits on an outer frame with spacing, so the next row no longer covers or interrupts it (checked with all rows marked as changed, ALL and SCENE); rows inside the Paint groups sorted in menu order (Aperture, Matrix, Gamma, Black).
- White Clip Level shown as a percentage (108.0 %) with buttons ±0,1 and ±1,0, like Step Gamma.
- Mk1 -> Mk2 conversion v2: Aperture Setting, Multi Matrix Setting and White Clip (Setting, Level) are carried from the Mk1 file, White Clip is switched off with S-Log2/S-Log3 like the camera does; new files in the converted files (v2).
- Preset Select (second dropdown of the preset matrix) is greyed out while the Preset Matrix is Off (new field option `enabled_when`); in ALL files BT.2020 is only selectable with a 4K/QFHD recording format (manual, FS7M2 round 10). User gammas 1 to 5 in the User select. Small database gaps closed (ALL `00422`, `00193`, scene `00142`).
- Adaptive Matrix (scene `00115` / ALL `00307`, new in `id_map.json`) as check box, locked with Matrix Off; User Matrix field order and Preset Select confirmed on the FS7M2 (round 9).
- Undo: the companion values of a choice (e.g. the Shooting Mode switch) now always belong to the undo step of that choice; before, a slow machine (> 1 s) could split it into two steps.
- **Multi Matrix** (scene `00074` / ALL `00178`) with an axis dropdown (B to B–, axes with a value marked) and hue/saturation steppers like the camera menu; Multi Matrix Setting as check box (`00002` / `00020`); Multi Matrix is greyed out when it or the Matrix Setting is Off (FS7M2 rounds 7 and 8).
- Aperture Setting and Matrix Setting as check boxes (scene `00037`/`00005`, ALL `00069`/`00023`, confirmed on the FS7M2, rounds 5 and 6); Aperture Off greys out the Aperture Level, Matrix Off greys out Preset Matrix and User Matrix.
- **Skin Detail** (scene `00025` / ALL `00054`, new group "Paint › Skin Detail"): Setting, Level, Saturation, Hue (0 to 359°, with a small colour field next to it) and Width (0 to 90°); step fields can have their own unit, range and sign per field. V Detail Creation: G = 1 (FS7M2 round 4).
- Detail menu, second part (FS7M2 round 3): Knee Aperture (On/Off with level lock), Knee Aperture Level, Limit, White Limit, Black Limit, V Black Limit as step fields and V Detail Creation (NAM, Y; G and G+R unassigned) in scene and ALL files.
- Detail menu (scene + ALL, FS7M2 round 2): Level, H/V Ratio, Crispening, Frequency and Level Depend Level as step fields, Level Depend as check box that greys out its level (new row locks via `ids`); the second copy of the detail values in the ALL file is entered as a hypothesis.
- **Detail Setting** (scene `00044` / ALL `00088`, check box, own group "Paint › Detail") greys out the other Detail settings (to be filled with the next rounds).
- Milestone reached: the sample set A scene files converted from the FS7 to the FS7M2 load on the real FS7M2 and show the intended Master Black, gamma and White Clip.
- **Step Gamma** (ALL `00043`, scene `00021`) as a number field shown as 0.45 with range 0.35 to 0.90 in steps of 0.05 (buttons ±0,05 / ±0,10; input with comma or point, snapped to the grid). The counter widget got an optional display scale.
- **White Clip Setting** (`00125` / scene `00068`, check box) greys out the White Clip level (`00126` / `00069`); confirmed on both cameras (FS7M2 014/015.ALL, FS7 031/032.ALL). The Gamma Category choice sets it like the camera does (On with STD/HG/User, Off with S-Log).
- Faster loading: the collapsed block of unknown parameters is built when it is opened, the table is built off screen; an ALL file opens in about 3.5 s instead of 6-10 s.
- **Gamma Category dropdown with a dependent Gamma Select, now also for SCENE files** (flags `00017` STD, `00019` HG, `00078` User, `00022` S-Log2, `00143` S-Log3; selects `00018` STD, `00085` HG); the same two-step dropdown in ALL files (with the User select `00191`). Gamma On/Off (`00023`) greys out the rest, Master Gamma `00024`. `id_map.json`: `00017` -> `00039`, `00143` -> `00494` (S-Log3 flag, confirmed by the Mk1 003/004 SCENE/ALL pairs).
- **Neu…** button: asks FS7 (Mk1) or FS7 Mk2 and starts a new file from the model's templates (SCENE and ALL profile, switchable) with neutral values from `defaults.json` (Master Black, Aperture Level, user matrix, multi matrix = 0). Not a factory dump: no complete default scene file is published.
- White Clip Level `00069` as a number field (90.0 to 109.0 %, value x 0.1 %) with the rules of the manual and the STD 105 % / HG 109 % rule of thumb as info text; `00068` marked as a possible White Clip Setting (untested).
- Mk1 -> Mk2 conversion maps Master Black by displayed step (value map in `_transfer`: Mk1 -2/-3/-5 -> Mk2 -827/-992/-1778, from the FS7M2 files 013/010/014.ALL); the converted sample set A files carry them.
- Milestone check: conversion of Mk1 scene files to FS7M2 scene files verified against sample set B's nine real Mk1/Mk2 pairs and the sample set A files (valid Mk2 ID set, exact round trip); the project notes holds everything off the goal.
- A parameter database that cannot be read (e.g. while it is being written) is retried and, if it still fails, reported in a dialog instead of silently showing only raw values.
- Paint › Black (ALL): **Black Setting** check box (`00031`: 0 = On, 1 = Off; before taken for a Cine EI flag) greys out the other Black settings, R Black `00029` and B Black `00030` as step fields; Master Gamma `00046` and R/G/B Gamma `00491`-`00493` as step fields (B Gamma -99 is stored as -32768). Step fields accept an asymmetric minimum (`min_raw`). Checked against the FS7M2 files 009-012.
- Gamma (ALL): **Gamma Category** dropdown (STD, HG, User, S-Log2, S-Log3; sets the flag combination `00039`/`00041`/`00044`/`00190` plus `00125`/`00494`), Gamma Select dropdowns per category (`00040` STD, `00042` HG, `00191` User), Step Gamma `00043` (0.45), and a **Gamma On/Off check box** (`00045`) that greys out all other Gamma settings. Locks can now overlap (Paint menu in Cine EI + Gamma Off). Checked against the FS7M2 files 001, 003–008.
- FS7M2 Custom -> Cine EI -> Custom now follows the camera files (the camera does not restore `00041`/`00125`: it stays on S-Log3).
- Format MPEG HD422 1920×1080 25p (FS7M2, 50 Mbit) from `own FS7M2 files 003.ALL` added to the format list.
- Model switch (FS7 <-> FS7M2) now also for ALL files (own profile per type and model; lost values come back when switching back; transfer rules apply via the SCENE IDs).
- Rec format cleaned up: **Codec** is a selection box and **Format** lists only the formats known for that codec (without naming the codec again); choosing a codec picks a format with the same resolution/frame rate if there is one. RAW codecs are greyed out in Custom mode; the derived resolution/frame rate/scan boxes are gone (they are part of the format text).
- FS7M2 ALL files: same IDs as the Mk1 plus seven new unknown ones (`00341`, `00472`–`00477`), so the ALL database, SCENE ↔ ALL switch, import and a template (`templates/PXW-FS7M2.ALL`) now work for the Mk2 too. ID map checked with a real SCENE/ALL pair (98 of 98 equal); the doubtful pairs `00139` (both models) and `00098` (Mk2) were removed.
- Closing the window or opening another file with unsaved changes asks whether to save (Yes / No / Cancel).
- New widget type `counter` (number entry with −10/−1/+1/+10 buttons) for the S&Q frame rate `00151` (1 to 180 fps) instead of the long dropdown; which rates are possible per codec/scan mode is not modelled yet.
- Import (Import…) from any SCENE/ALL file of either model into the current file: list with check boxes (all / none / invert / known only, search, "nur Unterschiede") or "Alles Bekannte importieren"; one undo step. Same type and model: identical IDs; otherwise via the SCENE ID space (`id_map.json`, transfer rules, `only_models`). ALL of the FS7M2 cannot be mapped yet.
- Locked type switch / model menu are highlighted: label gets a 🔒 and warning colour, tooltip names the reason (ALL: no model switch, Cine EI: no SCENE).
- Long hint texts (header messages, clip row, parameter notes) now sit behind an ⓘ symbol and appear as a tooltip on hover; plausibility warnings stay visible.
- Sub-groups (camera menu names) collapse and expand by clicking their heading (▼/▶); matches stay visible while a filter is active.
- Clip name row at the very top for ALL files (editable, linked with Title Prefix `00285`, undo/dirty aware); no start number field (the camera keeps the running clip number internally, it is not stored in ALL files); Camera ID / Reel Number / Camera Position (`00181`–`00183`, likely) added to the database.
